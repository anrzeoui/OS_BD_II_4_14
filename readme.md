# Contiguous Memory Allocation — Залгаа санах ой хуваарилалт

**F.CSM302 Үйлдлийн систем · Бие даалт 1 · II-4-14 баг**

Memory Lab нь **First Fit, Best Fit, Worst Fit** алгоритмаар процессуудад залгаа санах ой хуваарилах ажиллагааг загварчилсан Python программ юм. Санах ой хуваарилах, чөлөөлөх, сул хэсгүүдийг нэгтгэх, нягтруулах үйлдлийг командын мөрөөс болон график цонхоор туршина.

Төслийн зорилго нь **нийт сул зай хүрэлцээтэй байхад яагаад хүсэлт татгалзагддаг**, мөн **нягтруулалт энэ асуудлыг хэрхэн шийддэг** болохыг memory layout дүрслэлээр тайлбарлах юм.

## Үндсэн боломжууд

- **Гурван стратеги:** First Fit, Best Fit, Worst Fit сонгон санах ой хуваарилах.
- **Чөлөөлөлт:** процессын блокийг чөлөөлж, хөрш сул хэсгүүдийг автоматаар нэгтгэх.
- **Нягтруулалт:** процессуудын дараалал, хэмжээг хадгалан бага хаяг руу шилжүүлэх.
- **Memory layout:** эзэмшсэн болон сул блокуудыг хэмжээнд нь пропорционал зурвасаар харуулах.
- **Төлөвийн хүснэгт:** процесс, эхлэх/төгсөх хаяг, хэмжээ, төлөвийг харах.
- **Туршилтын удирдлага:** нийт хэмжээ, PID, хүсэлтийн хэмжээ, стратегийг өөрчлөх; reset хийх.
- **Алхамчилсан демо:** нэг алхмаар эсвэл автоматаар тоглуулах, түр зогсоох.
- **JSON export:** одоогийн төлөв, команд бүрийн өмнөх/дараах төлөв, амжилт/алдааг хадгалах.
- **Оролтын шалгалт:** буруу хэмжээ, давхардсан PID, үл мэдэгдэх команд, хүрэлцэхгүй зайг мэдээлэх.

> Энэ нь `0..MAX-1` логик хаягийг загварчилдаг сургалтын симулятор. Компьютерийн бодит RAM эсвэл kernel-ийн санах ойг хуваарилахгүй.

## Ашиглах заавар

### Командууд

| Команд | Үйлдэл | Жишээ |
| --- | --- | --- |
| `RQ PID size strategy` | Процесст залгаа блок олгох | `RQ P0 40000 W` |
| `RL PID` | Процессын блокийг чөлөөлөх | `RL P0` |
| `C` | Эзэмшсэн блокуудыг нягтруулах | `C` |
| `STAT` | Эзэмшсэн ба сул хаягийн мужуудыг харах | `STAT` |
| `X` | Программаас гарах | `X` |

Хэмжээг **bytes** нэгжээр оруулна. Хаягийн мужийн хоёр төгсгөл хоёулаа багтана: `[0:39999]` нь **40,000 bytes**.

| Сонголт | Алгоритм | Hole сонгох зарчим |
| --- | --- | --- |
| `F` | First Fit | Хаягийн өсөх дарааллаар эхний багтах сул хэсэг |
| `B` | Best Fit | Хүсэлтийг хангах хамгийн жижиг сул хэсэг |
| `W` | Worst Fit | Хамгийн том сул хэсэг |

Ижил хэмжээтэй hole-уудаас бага хаягтайг сонгоно. PID нь үсгээр эхэлсэн, 1–32 латин үсэг/цифр/`_` тэмдэгтээс бүрдэнэ; `P0` ба `p0` ялгаатай. Давхардсан PID-г зөвшөөрөхгүй. Нийт хэмжээ `1..2^63-1`, хүсэлтийн хэмжээ эерэг бүхэл тоо байна.

### График цонх

1. **Нийт bytes** талбарт хэмжээг оруулаад **Reset** дарна.
2. **PID**, **Bytes**, **F/B/W** сонголтыг тохируулж **RQ • Хуваарилах** дарна.
3. Процесс чөлөөлөхдөө PID-г оруулж **RL • Чөлөөлөх** дарна. Хүснэгтийн мөрөөс PID сонгож болно.
4. **C • Нягтруулах** товчоор блокуудыг бага хаяг руу шилжүүлнэ.
5. **Демо бэлтгэх → Алхам** эсвэл **Тоглуулах** товчоор жишээ туршилтыг ажиглана.

Өнгөт хэсэг нь процесс, саарал хэсэг нь сул **hole**. Нарийн блокийн шошго багтахгүй үед яг хаяг, хэмжээг хүснэгтээс харна. `allocator>` талбарт дээрх командуудыг бичиж ажиллуулж болно.

**Reset** нь өмнөх төлөв, түүхийг арилгана. Шаардлагатай бол эхлээд **JSON хадгалах** дарна. **Зогсоох** нь демог түр зогсооно; гар команд ажиллуулахад демогийн үргэлжлэл цуцлагдана. JSON импортлох боломж одоогоор байхгүй.

## Туршилтын жишээнүүд

### 1. Сурах бичгийн жишээ

```bash
python3 -m src.cli 1048576 --file examples/book.txt
```

`RQ P0 40000 W` командын дараа P0 нь `[0:39999]` хаягийг эзэмшиж, **1,008,576 bytes** сул үлдэнэ. `RL P0` хийсний дараа бүх санах ой нэг сул блок болно.

### 2. External fragmentation ба compaction

```bash
python3 -m src.cli 1000 --file examples/fragmentation.txt
```

| Үе шат | Санах ойн төлөв / үр дүн |
| --- | --- |
| P0=300, P1=200, P2=300 bytes хуваарилах | 800 bytes эзэмшсэн, 200 bytes сул |
| P0-г чөлөөлөх | 300 ба 200 bytes хэмжээтэй хоёр hole; нийт сул 500 |
| P3-д 400 bytes хүсэх | Хамгийн том hole 300 тул хүсэлт татгалзана |
| `C` командаар нягтруулах | 500 bytes хэмжээтэй нэг залгаа hole үүснэ |
| P3-д дахин 400 bytes хүсэх | P3 `[500:899]` мужийг эзэмшинэ; 100 bytes сул үлдэнэ |

**Энэ жишээнд эхний 400 bytes хүсэлт зориудаар татгалзагдана.** Скрипт дараагийн командуудаа үргэлжлүүлж, төгсгөлд exit code `1` буцаах нь хүлээгдсэн үр дүн юм.

[Нягтруулахаас өмнөх зураг](docs/memory-fragmented.png) · [Татгалзсан хүсэлт](docs/memory-rejected.png) · [Нягтруулсны дараах зураг](docs/memory-compacted.png)

### 3. F/B/W стратегийн ялгаа

```bash
python3 -m src.cli 1500 --file examples/strategies.txt
```

Энэ файл нь First Fit-ийн жишээ. `RQ Q 150 F` мөрийн сүүлийн сонголтыг `B`, дараа нь `W` болгож, программыг шинээр эхлүүлэн ижил нөхцөлд харьцуулна.

| Стратеги | Сонгосон hole-ийн хэмжээ | Q процессын муж |
| --- | --- | --- |
| First Fit | 400 bytes | `[0:149]` |
| Best Fit | 200 bytes | `[500:649]` |
| Worst Fit | 600 bytes | `[900:1049]` |

### Fragmentation үзүүлэлт

GUI дээрх `F` хэмжүүрийг `1 - largest_hole / free` гэж тооцно; сул зай `0` үед `0` гэж авна. Жишээлбэл, 300 ба 200 bytes сул хэсэгтэй үед `F = 40%`.

Эндэх `F` хэмжүүр нь стратегийн `F` сонголтоос тусдаа ойлголт. `F = 0%` нь хүсэлт заавал амжилттай гэсэн үг биш: санах ой бүрэн дүүрсэн байж болно.

## Репогийн бүтэц

| Зам | Зориулалт |
| --- | --- |
| `src/allocator.py` | Block загвар, хуваарилалтын алгоритм, validation, командын parser |
| `src/cli.py` | Интерактив командын мөр болон файл дахь командуудыг ажиллуулах |
| `src/gui.py` | Tkinter цонх, memory layout, демо, JSON export |
| `tests/test_allocator.py` | Нэгж, интеграц болон санамсаргүй тест |
| `tests/gui_smoke.py` | GUI-ийн үндсэн ажиллагааны шалгалт |
| `examples/` | Номын жишээ, fragmentation, стратеги харьцуулах оролтууд |
| `docs/` | Тайлан, гарын авлага, screenshot, тестийн гаралт |

CLI ба GUI нь **нэг `Allocator` цөм** ашигладаг. Санах ойг `Block(start, size, pid)` жагсаалтаар хадгалж, `pid=None` үед сул блок гэж үзнэ. `request()`, `release()`, `compact()` нь блокийн тооноос хамаарах **O(n)** хугацаатай.

## Түгээмэл асуудал

| Асуудал | Шийдэл |
| --- | --- |
| `No module named src` | `OS_BD_II_4_14` үндсэн хавтсаас командыг ажиллуулах |
| `No module named tkinter` | Linux дээр `python3-tk`, Windows дээр Python-ийн Tcl/Tk бүрэлдэхүүнийг суулгах |
| `no display` / дэлгэцтэй холбоотой `TclError` | График desktop орчин ашиглах эсвэл CLI горимоор ажиллуулах |
| Нийт сул зай хүрэлцэх боловч RQ татгалзах | Хамгийн том hole-ийг шалгах; шаардлагатай бол `C` ажиллуулах |
| PID давхардсан эсвэл олдохгүй | PID-ийн бичлэг, том/жижиг үсэг, `STAT` гаралтыг шалгах |

Симулятор нь paging, swap, alignment, бодит процессын өгөгдөл шилжүүлэх зардлыг загварчлаагүй. Нэг PID нэг блок эзэмшинэ; resize/realloc байхгүй. Тайланд дурдсан туршилтын орчин нь Ubuntu 24.04.3 LTS, Python 3.12, Tcl/Tk 8.6; Windows ба Debian дахь ажиллагааг өөрийн төхөөрөмж дээр давтан шалгана.
